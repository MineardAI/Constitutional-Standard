# IMP Realization Dependency and Gate Matrix

| Target | Required upstream | Entry gate | Exit gate | Required evidence |
|---|---|---|---|---|
| IMP-004 traceability completion | IMP-000/001/002/003 partial foundation; CORE closure | source register, ownership matrix, current mappings, scope and deviation baseline reviewed | Complete for bounded typed traceability: subjects, relations, bindings, deterministic findings, mandatory paths, and non-authority flags | `TRACEABILITY_*` profile/validation/boundary records, eight focused tests, EV-TRACE-0001 |
| IMP-005 canonical expansion | IMP-004 mapping identity; existing canonical foundation | representation ownership and public-object inventory approved | Complete for bounded shared model: typed forms, strict deterministic binding, unknown/duplicate/order rejection, round trips, compatibility, and representation non-identity tests | canonical realization/boundary/identity/compatibility profiles, eight focused tests, EV-CANON-0001 |
| IMP-006 verification/assurance | IMP-003 gates; IMP-004 mappings; IMP-005 representations | obligations and finding classes bound to scope | Complete for bounded deterministic verification and explicitly scoped, limited, version/source-bound assurance; no conformance or certification | verification/assurance profiles, 11 focused tests, EV-VERIFY-0001 |
| IMP-007 evidence/provenance | IMP-004 mappings; IMP-006 obligations | evidence identity/provenance ownership and source bindings approved | versioned attributable evidence packages and lineage records; sufficiency remains distinct | evidence profile, provenance tests, evidence record |
| IMP-008 release/continuity | IMP-003/004/005/006/007 | release semantics and compatibility ownership reviewed | continuity/compatibility records preserve history without activation | release profile, migration/conflict tests, evidence record |
| IMP-009 activation/recognition | IMP-003/007/008 plus explicit applicable authority | separate authority and operational-boundary review | bounded determinations/records plus explicit lifecycle/history and resolution validation; no runtime activation performed | activation profile, negative/prohibition tests, evidence record, closure remediation record |

The closure remediation rechecks the IMP-007/008/009 boundary by requiring explicit typed bindings for release, evidence, authority, jurisdiction, authorization, compatibility, migration, and traceability references. It does not change the source register or elevate candidate/draft source status.

The second remediation adds the residual gate checks for ordered lifecycle history, recognition decision/criteria/version bindings, evidence finding reachability and custody continuity, migration/supersession graph closure, release history, and release-to-activation traceability. These checks remain bounded validation and do not change dependency ownership.

## Universal gate conditions

Every gate requires exact source/version/status binding, declared scope and exclusions, component ownership, dependency review, canonical representation where applicable, forward/reverse/negative traceability, reproducible tests, evidence identity, deviation disposition, and explicit non-authority/non-execution declarations. Missing, contradictory, or ambiguous source material yields recorded indeterminacy or a blocked gate; it is never silently resolved.
